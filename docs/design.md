# jht — Technical design

The algorithm, conventions, and differentiability design of jht. The measured accuracy
contract is in `docs/accuracy.md`; the performance characterisation is in
`docs/performance.md`.

## Why jht

The established high-accuracy SHT libraries (ducc0, healpy) are compiled, CPU-only C++.
jht covers work they cannot serve:

- **GPU execution:** forecast sweeps, the inner Wiener solve of field-level inference,
  and large simulation ensembles.
- **End-to-end differentiability:** gradients through the transform, and on the off-grid
  path through the evaluation pointings, which a compiled FFI does not expose.
- **Dependency control:** pure JAX + NumPy installs with `pip` and needs no C++/CUDA
  build toolchain.

The leading JAX-native alternative, s2fft, has a precision defect in spin-2 HEALPix
analysis: single-mode errors of 3–28% at band limits well below the sampling ceiling
(v1.3.0–1.4.0). jht is a clean-room implementation informed by the published methods,
with spin-2 accuracy as an explicit gate. It was written for GPU and differentiable
CMB analysis.

jht targets the tier where the HEALPix sampling floor (~1e-3, closed to ~1e-13 on
band-limited maps by ring weights + iteration) is acceptable. It does not replace a
purity-critical (~1e-4) CPU production transform.

## Accuracy tiers

HEALPix has **no sampling theorem**, so a HEALPix SHT is intrinsically approximate.

| Tier | What it is | Measured (broadband) |
|---|---|---|
| Bare floor | direct quadrature, uniform `4π/Npix` | ~2–17e-3 |
| + ring weights | jht's minimum-norm ring weights (`jht.weights`) | ~2–12e-4 |
| + Jacobi iteration | `analysis`, band-limited input | **~1e-13** |

- **No spin-2 defect:** spin 2 sits at the same ~1e-3 bare floor as spin 0.
- **The a-priori contract** is weighted + `niter=3` ≤ 1e-4 (measured ~1e-13).
- **Ring weights are jht's own,** not HEALPix's shipped `weight_ring` arrays (those
  come from a different, undocumented solver and would need data files). They are
  the minimum-norm per-ring correction that makes the m=0 quadrature exact to
  `Lw = 2·nside`, validated end to end rather than by array match. Algorithm and
  numbers: `docs/accuracy.md`.

## Algorithm

- **Synthesis (aₗₘ → map):** per ring, the normalized associated-Legendre (spin 0) or
  spin-weighted (spin 2) functions are generated by an ℓ-recursion and contracted with
  aₗₘ over ℓ to give per-m ring coefficients, then an FFT over φ along each ring.
  - The recursion is vectorized over m (one fused `lax.scan` per spin).
  - The φ-FFTs are batched by ring length: the equatorial belt in one FFT, the polar
    caps by length group, or a looped/chirp-z mode with O(1) compiled kernels
    (`jht.set_azimuth_fft_mode`).
- **Adjoint (map → aₗₘ):** the exact transpose of synthesis — per-ring FFT, then
  contract with the same functions.
- **Analysis:** the adjoint with ring quadrature weights, Jacobi-iterated toward the
  inverse on band-limited maps.
- **Static data:** geometry, recursion plans and index maps are built once per
  `(nside, lmax, spin)`. Large static tables are generated in-trace behind
  `optimization_barrier` rather than closed over, so programs with many transforms do
  not embed a copy per use as XLA constants.

### Recursion stability

Associated-Legendre recursions underflow at high ℓ: the seed `P̄_mm` carries
`(sin θ)^m`. jht uses the three-term recursion in ℓ at fixed (m, s)
(Kostelec–Rockmore 2008; libsharp Eq. 10–11), run in the **increasing-ℓ** direction
(libsharp §4.1).
- **Stabilization:** a branch-free per-step log-renormalization divides the running
  pair by `|d_ℓ|` and accumulates `log|d_ℓ|` (the Price & McEwen technique for the
  recursion only, not their m-recursion). It runs as a fixed-trip `lax.scan`, so it is
  clean under `jit` / `vmap` / `grad`.
- **One code path:** spin 0 is m′ = 0 and spin 2 is m′ = s = 2 (libsharp §5.1.2
  shows spin 2 reaches the same accuracy with this machinery).
- **Measured** exact to ℓ = 32000.
- **Avoided:** the Risbo / Trapani–Navaza Δ(π/2)-matrix family (O(L²) memory per ℓ,
  double-precision instability near L ~ 2048), and threshold-gated rescaling (a
  data-dependent branch).

### Spin-2 analysis quadrature

A spin-2 HEALPix analysis can fail with a localized single-mode leakage signature
(m ≈ ℓ clean, m < ℓ off by O(10%)). That comes from aliasing / polar folding plus
missing ring weights, and an unweighted Jacobi iteration does not remove it. jht owns
the weighted spin-2 analysis and validates it per (ℓ, m) below the ℓ ≤ 1.5·nside
ceiling, using single-mode sweeps across all m rather than round-trip totals (which
hide localized leakage).

## Conventions (verified against healpy 1.19.0 and ducc0 0.41.0)

healpy and ducc0 agree on the transform seam. The only divergence is the IAU U-flip,
which belongs at the application layer.

- **aₗₘ layout:** m-major triangular, only m ≥ 0 stored (real maps imply
  `a_{ℓ,−m} = (−1)^m conj(a_{ℓ,m})`). Index `idx(ℓ,m) = m·(2·ℓmax+1−m)//2 + ℓ`, size
  `(ℓmax+1)(ℓmax+2)/2`, m=0 real. Matches `healpy.Alm`.
- **Normalization:** orthonormal `Y_ℓm` with the Condon–Shortley phase,
  `map = Σ a_ℓm Y_ℓm`. There is no extra 4π factor: a constant map c gives
  `a₀₀ = √(4π)·c`.
- **Spin 2:** `(Q ± iU) = Σ ±₂a_ℓm · ±₂Y_ℓm` with `₊₂a = −(aE + i·aB)`,
  `₋₂a = −(aE − i·aB)`. healpy `alm2map(pol=True)` equals ducc `synthesis(spin=2)` to
  ~5e-13 with the same sign.
- **Polarization:** HEALPix-internal (COSMO), the healpy default; `U_IAU = −U_HEALPix`.
- **No pixel window** is applied (healpy `pixwin=False`).

## Differentiability

The on-grid SHT is linear in aₗₘ and differentiates under JAX's **native** autodiff by
default: `jax.grad` / `vjp` / `jacrev` / `jacfwd` all work.
- **Why no default `custom_vjp`:** it would block forward mode, and keeping forward
  mode while routing reverse through a hand kernel would need JAX-internal primitives.
- **Scatters:** forward scatters carry `unique_indices=True` so the kernels transpose
  cleanly.

- **Reverse-mode memory.** Native AD through the recursion scan would store one
  `(lmax+1, lmax+1, 2·nside)` table per transform (~nside³ bytes) for the backward
  pass.
  - Every on-grid kernel runs under a save-nothing `jax.checkpoint`, so under `grad`
    of a scanned body the grid-only recursion is not hoisted out as a stacked
    constant.
  - `jht.synthesis_vjp` / `adjoint_synthesis_vjp` carry a transpose-pair `custom_vjp`
    (each VJP is one call to the partner kernel): native AD's cotangents with no
    recursion tape, at the cost of forward mode. Use them for `grad` at high nside.
- **Three distinct operators.** Keep them separate:
  - `adjoint_synthesis = Sᵀ` is the exact, weight-free transpose: the operator a
    linear solve needs.
  - `analysis` (weighted + iterated, aka `map2alm`) is the approximate inverse.
  - The AD cotangent is neither.
- **The `2·conj` convention.** Packed aₗₘ store only m ≥ 0, so the aₗₘ inner product
  carries the metric `G = 2 − δ_{m0}` (`jht.alm_metric_weight`). JAX's reverse mode
  returns the Euclidean cotangent in this packing:

      jax.vjp(synthesis)(v)  ==  G ⊙ conj(adjoint_synthesis(v))

  This is exact for spin 0 and for spin 2 at m > 0 (`tests/test_grad.py`), so
  `jax.grad` is finite-difference consistent (JAX's complex gradient is
  `dL/dRe − i·dL/dIm`).
- **Spin-2 m=0.** `synthesis` keeps both Re→Q and Im→U at every m, so the map depends
  on the unphysical Im(aₗ₀) at m=0, and the native cotangent carries an E/B-mixing
  term there (`cot_E = bE − i·bB`, `cot_B = bB + i·bE`). Physical fields have real aₗ₀.
  The real-DOF layer drops this direction.
- **Real-DOF layer (recommended for gradients).** `synthesis_real` / `analysis_real`
  act on the real isometry coordinates `x` (`‖x‖₂ = ‖a‖_w`): plain `ℝⁿ → ℝᵐ` maps with
  no conjugation convention. There, `jacfwd ≡ jacrev` exactly and finite differences
  are unambiguous. `bandpower` gives Cℓ with the `G` fold (== `healpy.alm2cl` to 1e-16).
- **Gated** (`tests/test_grad.py`, 1e-12 algebraic / 1e-6 FD):
  - `jacfwd ≡ jacrev`, and ⟨S a, v⟩ = ⟨a, Sᵀ v⟩;
  - native VJP == the `G` bridge, and FD agreement;
  - `jit` / `vmap` cleanliness. Call a transform once before the first `vmap`, so the
    static-layout cache is not first populated inside a trace.
- **Pointing differentiability** belongs to the off-grid transforms
  (`docs/offgrid.md`).

## Non-goals

- Arbitrary spin; non-HEALPix samplings.
- A compiled (C++/CUDA) kernel. Pure JAX is a deliberate property; changing it is a
  major decision.

## Validation harness

- Parity tests against healpy (`alm2map` / `map2alm`, `pol=True`) and ducc0 for every
  transform, at documented a-priori tolerances.
- Single-mode sweeps across all m to catch localized leakage that round-trip totals
  hide.
- `DISCREPANCIES.md` logs any residual mismatch: where seen, suspected cause, what would
  close it.
